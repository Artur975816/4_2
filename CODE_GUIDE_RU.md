# Руководство по коду игры

Это объяснение относится к проекту `D:\Unity\artur123123` на момент создания файла. Оно описывает назначение каждого C#-файла, написанного для проекта, и общий путь событий в игре. В Unity Inspector значения публичных полей можно менять без изменения кода.

## Как устроена игра в целом

1. До загрузки первой сцены `RuntimeLevelBootstrap` создаёт постоянные объекты настройки уровня и `GameManager`.
2. При загрузке сцены менеджер сбрасывает данные текущего уровня, находит игрока и считает монеты. Настройщик добавляет недостающие компоненты и мобильные кнопки.
3. `PlayerMovement` получает управление с клавиатуры, геймпада или виртуального джойстика. В `FixedUpdate` он двигает Rigidbody2D и прыгает.
4. Монета вызывает `Coin`, который увеличивает счёт уровня через `GameManager`; выход `Exit` проверяет, собраны ли все монеты.
5. Получение урона идёт через `Health` из пространства имён `Assignment6` (файл называется `Health1.cs`). При потере жизни `GameManager` возвращает игрока к контрольной точке или показывает поражение.
6. На третьем уровне `BossController` принимает урон от `Bullet`, обновляет Slider здоровья и при нуле здоровья сообщает менеджеру о победе.
7. `UIManager` отображает счёт, жизни, паузу, победу, поражение и временные сообщения. `SaveSystem` хранит прогресс и громкость между запусками.

## Словарь Unity

- `Awake` вызывается при создании/активации компонента и подходит для начальной настройки ссылок.
- `Start` вызывается перед первым обновлением компонента.
- `Update` вызывается каждый кадр; здесь удобно читать клавиши и обновлять визуальные параметры.
- `FixedUpdate` вызывается с фиксированным шагом физики; перемещение Rigidbody2D лучше делать здесь.
- `OnTriggerEnter2D` — событие входа коллайдера в триггер. Для него один из Collider2D должен быть триггером и в паре обычно требуется Rigidbody2D.
- `OnCollisionEnter2D` — физическое столкновение, не триггер.
- `SerializeField`/`public` поле можно назначать и настраивать в Inspector.
- `Singleton` — доступ к единственному экземпляру через статическое свойство, например `GameManager.Instance`.

## Core — управление игрой

### `Assets/Scripts/Core/GameManager.cs`
Главный менеджер игрового цикла. Хранит жизни, монеты именно текущего уровня, контрольную точку и флаги победы/поражения. При загрузке сцены считает объекты `Coin`, настраивает игрока и обновляет HUD. `AddCoin` увеличивает счёт уровня; `LoseLife` уменьшает жизни и возрождает игрока либо включает Game Over; `WinLevel` останавливает игру и показывает экран победы, затем загружает целевую сцену. Также здесь находятся пауза, рестарт, переход в меню и выбор следующего уровня. Он не хранит глобальную валюту — за неё отвечает `SaveSystem`.

### `Assets/Scripts/Core/RuntimeLevelBootstrap.cs`
Автоматический настройщик сцен. Создаётся до загрузки сцен и остаётся между ними. Следит за `sceneLoaded`, убеждается, что существует EventSystem с UI-модулем новой Input System, добавляет мобильный джойстик/кнопки и Safe Area, а для сцен с недостающей UI создаёт Canvas и панели. Для третьего уровня собирает арену, персонажей, босса и Slider здоровья. Также содержит вспомогательные методы создания платформ, стен, текста, кнопок и простых runtime-спрайтов. Это большой инфраструктурный скрипт, а не контроллер игрового персонажа.

### `Assets/Scripts/Core/BossController.cs`
Логика босса: движение внутри границ арены, прыжки, выстрелы и ударные волны при приземлении. `TakeDamage` уменьшает здоровье, обновляет связанный UI Slider и визуально мигает спрайтом. При нулевом здоровье босс отключает коллайдеры, удаляет свои снаряды, вызывает победу менеджера и уничтожается. Для полосы важна назначенная ссылка на Slider; в автоматически построенной арене её передаёт `RuntimeLevelBootstrap.SetHealthBar`.

### `Assets/Scripts/Core/BossShockwave.cs`
Снаряд-волна босса. Движется в заданном направлении и удаляется после заданной дальности. При попадании в игрока наносит урон через `Assignment6.Health` (или снимает жизнь как запасной путь), затем уничтожается. Направление задаётся при создании волны, поэтому она не наводится за игроком.

### `Assets/Scripts/Core/AudioManager.cs`
Постоянный менеджер музыки и звуковых эффектов. Создаётся до сцены, загружает музыку из `Resources/Audio/BGM_Platformer`, запускает её по кругу и выставляет громкости из сохранений. `SetMusicVolume`/`SetSfxVolume` применяют и сохраняют значения; `PlaySfx` проигрывает одноразовый звук.

### `Assets/Scripts/Core/SaveSystem.cs`
Небольшой слой над Unity `PlayerPrefs`. Хранит общие монеты, открытый уровень и громкость музыки/эффектов. Значения переживают закрытие игры. Монеты уровня отдельно считает `GameManager`, поэтому HUD уровня может начинаться с нуля.

### `Assets/Scripts/Core/A6GameManager.cs`
Упрощённый менеджер из ранней версии задания Assignment 6: таймер, здоровье, спавнер, ворота, победа/поражение и перезапуск. Он относится к старой самостоятельной мини-игре и не является основным менеджером платформера (основной — `GameManager.cs`). Если сцена использует оба компонента, важно не перепутать их обязанности.

## Player — персонаж и атака

### `Assets/Scripts/Player/PlayerMovement.cs`
Основной контроллер персонажа. Читает A/D и стрелки, Space/W/стрелку вверх, геймпад и значение `MobileJoystick.Current`. Запоминает короткое нажатие прыжка (jump buffer), даёт небольшой допуск после схода с края (coyote time), обрезает прыжок при отпускании кнопки и усиливает падение. В физическом цикле рассчитывает скорость, проверяет землю несколькими лучами, учитывает скорость движущейся платформы и переворачивает спрайт по направлению. Высота прыжка задаётся через `jumpHeight`; настройщик выставляет 2.5. В проекте используется новая Input System, поэтому здесь нет чтения через старый `UnityEngine.Input`.

### `Assets/Scripts/Player/PlayerAnimator.cs`
Передаёт состояние персонажа в Animator: скорость по горизонтали, вертикальную скорость и касание земли. Также ориентирует SpriteRenderer по направлению движения. Сам клипы не создаёт: контроллер и кадры лежат в ресурсах анимации, а контроллер назначает `RuntimeLevelBootstrap`.

### `Assets/Scripts/Player/MobileJoystick.cs`
Виртуальный джойстик UI. Реализует события указателя: нажатие, перетаскивание, отпускание. Преобразует горизонтальное смещение пальца относительно центра основания в значение примерно от -1 до 1, доступное через `MobileJoystick.Current.Horizontal`. Видимая дочерняя ручка двигается вслед за пальцем и ограничивается радиусом `maxDragDistance`; при отпускании возвращается в центр. На сцену добавляется `RuntimeLevelBootstrap`.

### `Assets/Scripts/Player/MobileControlButton.cs`
Обработчик мобильных кнопок. При нажатии кнопка прыжка вызывает `QueueJump`, при отпускании — `CutJump` для контроля высоты. Кнопка огня вызывает `Shooter1.Fire`. Реализует pointer-события, поэтому подходит для мыши и касания.

### `Assets/Scripts/Player/Shooter1.cs`
Обрабатывает стрельбу: клавиша X, геймпадная кнопка West, клик мыши или мобильная кнопка. Проверяет задержку между выстрелами, направление персонажа и состояние игры, проигрывает звук и создаёт пулю. Если спрайта пули нет в ресурсах, рисует простой временный спрайт.

### `Assets/Scripts/Player/Bullet.cs`
Движение и попадание пули игрока. Получает направление/скорость/урон от `Shooter1`, летит ограниченное время. При столкновении с боссом вызывает `BossController.TakeDamage`, с обычным врагом — `Enemy.TakeDamage`; при прочих твёрдых объектах уничтожается.

### `Assets/Scripts/Player/BossProjectile.cs`
Снаряд босса. Движется по заданному направлению и живёт ограниченное время. При попадании в игрока наносит урон через `Assignment6.Health` или запасной механизм потери жизни.

### `Assets/Scripts/Player/Health1.cs`
Несмотря на имя файла, класс называется `Health` и находится в `Assignment6`. Это рабочее здоровье игрока: максимум HP, неуязвимость после удара, мигание спрайта, лечение, звук и обновление HUD. При нуле здоровья сообщает `GameManager` о потере жизни (либо старому `A6GameManager`, если основной менеджер отсутствует). После возрождения `RestoreAfterRespawn` восстанавливает здоровье.

### `Assets/Scripts/Player/Health.cs`
Пустая старая заготовка с классом `Health` без логики. Она отличается от реального компонента `Assignment6.Health` в `Health1.cs`. Не путайте типы: скрипты платформера используют тип из пространства имён `Assignment6`.

### `Assets/Scripts/Player/CameraFollow.cs`
В `LateUpdate` плавно двигает камеру за целью с заданным смещением. `LateUpdate` выбран, чтобы камера обновилась после движения персонажа.

## World — объекты уровня

### `Assets/Scripts/World/Coin.cs`
Монета слегка покачивается и вращается. При входе игрока в её триггер проигрывает звук, увеличивает счёт уровня через `GameManager`, общую валюту через `SaveSystem`, обновляет HUD и удаляется.

### `Assets/Scripts/World/Exit.cs`
Дверь/выход уровня. При касании игроком сравнивает собранное и требуемое число монет. Если не всё собрано, показывает подсказку. Если условие выполнено, открывает следующий уровень и вызывает победу с целевой сценой. Переход активируется только один раз.

### `Assets/Scripts/World/Checkpoint.cs`
Контрольная точка. При касании регистрирует позицию игрока в `GameManager`, меняет цвет и больше не срабатывает повторно.

### `Assets/Scripts/World/Enemy.cs`
Простой враг с запасом здоровья. Получает урон от пуль и уничтожается при нуле HP. При касании игрока снимает здоровье или жизнь.

### `Assets/Scripts/World/EnemyMovement.cs`
Двигает врага туда-сюда между двумя точками. Если точки не назначены, использует колебательное движение вокруг исходного места.

### `Assets/Scripts/World/HazardTrigger.cs`
Триггер опасности. При входе игрока наносит указанное число единиц урона через компонент здоровья либо запасной механизм потери жизни.

### `Assets/Scripts/World/PitTrigger.cs`
Триггер падения за пределы уровня. Срабатывает один раз на вход, снимает жизнь и возвращает игрока через логику `GameManager`; сбрасывает внутренний флаг для следующего падения.

### `Assets/Scripts/World/MovingPlatform.cs`
Кинематическая платформа, которая ходит между исходной точкой и точкой со смещением. Может ждать на концах маршрута. Вычисляет собственную скорость и сообщает её контроллеру игрока, если тот стоит сверху, чтобы персонаж не скользил относительно платформы.

### `Assets/Scripts/World/InfiniteBackground.cs`
Параллаксный/зацикленный фон. Запоминает движение камеры и смещает фон с заданным коэффициентом. Когда камера проходит ширину фонового спрайта, фон переносится на следующую позицию, чтобы скрыть край плитки.

## UI — меню и интерфейс

### `Assets/Scripts/UI/UIManager.cs`
Обновляет текст монет и жизней, управляет панелями паузы, победы и поражения, показывает временные сообщения, запускает продолжение, рестарт и загрузку сцен. Существует как единственный активный UIManager сцены.

### `Assets/Scripts/UI/MenuManager.cs`
Методы для кнопок меню: открыть выбор уровней, настройки, вернуться в главное меню или выйти из приложения.

### `Assets/Scripts/UI/LevelSelector.cs`
Настраивается на кнопку уровня. При запуске проверяет `SaveSystem.UnlockedLevel` и блокирует закрытые уровни. `LoadLevel` загружает сцену `LevelN`, если она открыта.

### `Assets/Scripts/UI/SettingsManager.cs`
Связывает ползунки громкости с `AudioManager`/`SaveSystem` и dropdown качества графики с `QualitySettings`. При открытии выставляет сохранённые значения; при уничтожении снимает обработчики громкости.

### `Assets/Scripts/UI/PauseButton.cs`
Тонкий адаптер для UI-кнопки паузы: вызывает `GameManager.TogglePause()`.

### `Assets/Scripts/UI/SafeArea.cs`
Подгоняет RectTransform панели под `Screen.safeArea`, то есть область экрана без системных вырезов и небезопасных краёв. Пересчитывает нормализованные anchors при изменении размера, ориентации или safe area. `RuntimeLevelBootstrap` создаёт такую панель под Canvas и помещает внутрь неё UI-элементы; полноэкранный фон камеры при этом остаётся отдельным.

## Audio — звуки Assignment 6

### `Assets/Audio/A6Audio.cs`
Компонент звуков персонажа: выстрел, урон, подбор, взрыв, победа и прыжок. Может загрузить клипы из `Resources`, воспроизводит через общий `AudioManager`, а если его нет — через локальный AudioSource. Статические `Play...` методы позволяют другим компонентам вызвать нужный звук.

## Hazards — старые/отдельные компоненты задания

Эти файлы относятся к старой системе падающих препятствий Assignment 6. Основные уровни платформера используют `HazardTrigger`, `PitTrigger` и `BossShockwave`.

### `Assets/Scripts/Hazards/Hazard1.cs`
Базовый класс `Assignment6.Hazard`: поле урона, обработка физического столкновения с игроком и вызов `OnHitPlayer`. По умолчанию после удара объект удаляется; сердце переопределяет это поведение лечения.

### `Assets/Scripts/Hazards/BombHazard1.cs`
Бомба на таймере. Через `fuseSeconds` взрывается, проигрывает звук, при наличии создаёт визуальный эффект и наносит урон игрокам в радиусе. Радиус можно увидеть в Scene Gizmos.

### `Assets/Scripts/Hazards/Heart1.cs`
Аптечка в старой системе: переопределяет попадание и восстанавливает игроку 1 HP.

### `Assets/Scripts/Hazards/Rock1.cs`
Камень старой системы опасностей; использует обычное поведение базового `Hazard`.

### `Assets/Scripts/Hazards/Spawner.cs`
Периодически создаёт случайный prefab из массива `prefabs` в случайном диапазоне X и на заданной высоте. Если массив не настроен, выводит предупреждение. `StopSpawning` останавливает повторный вызов.

### `Assets/Scripts/Hazards/Bomb.cs`
Пустая заготовка без поведения. Не путайте её с рабочим `BombHazard1.cs`, где класс называется `Assignment6.BombHazard`.

## Editor — инструменты редактора Unity

### `Assets/Editor/ProjectRepairTools.cs`
Набор команд меню Unity `Tools > Project Repair`. Это редакторские операции, а не код, исполняющийся во время игры. Команды создают/пересобирают меню и настройки, арену третьего уровня, непрерывный фон второго, маршруты первого/второго уровней, анимационные кадры и Animator Controller, назначают общий контроллер персонажа и стены. Вспомогательные методы рисуют текстуры/кадры, создают платформы/монеты/опасности/UI и настраивают переходы Animator. Перед повторным запуском bake-команды стоит сохранить сцену: они могут менять содержимое сцены и связанные assets.

## Главные связи между компонентами

```text
Keyboard / Gamepad / MobileJoystick
              ↓
        PlayerMovement ──→ PlayerAnimator
              ↓
       Assignment6.Health ← Hazard / Enemy / BossProjectile
              ↓
         GameManager ──→ UIManager

Coin ──→ GameManager (счёт уровня)
  └────→ SaveSystem (общие монеты)
Exit ──→ проверка монет ──→ GameManager.WinLevel
Shooter1 ──→ Bullet ──→ BossController.TakeDamage ──→ Slider здоровья
BossController ──→ BossProjectile / BossShockwave
```

## Что важно не перепутать

- `GameManager.cs` — основной менеджер платформера; `A6GameManager.cs` — менеджер старого задания.
- `Assets/Scripts/Player/Health1.cs` содержит рабочий класс `Assignment6.Health`; `Assets/Scripts/Player/Health.cs` — пустой старый класс без пространства имён.
- `HazardTrigger` и `PitTrigger` — опасности платформенных уровней; `Hazard1`/`BombHazard1`/`Rock1`/`Heart1` — отдельная система старого задания.
- `RuntimeLevelBootstrap` создаёт часть UI и мобильного управления при загрузке уровня. Поэтому некоторые объекты могут быть видны в Play Mode, но отсутствовать в сохранённой сцене.
- Имена файлов с суффиксом `1` не всегда совпадают с именем класса внутри. Для понимания нужно смотреть на объявление класса и namespace.

## Как разбирать любой скрипт самому

1. Сначала найди `class ... : MonoBehaviour` — это компонент, который можно повесить на GameObject.
2. Посмотри публичные поля в начале класса: это параметры Inspector и ссылки на другие объекты.
3. Найди Unity callbacks (`Awake`, `Start`, `Update`, `FixedUpdate`, `OnTrigger...`, `OnCollision...`) — они показывают, когда код исполняется.
4. Для каждого метода проследи, кто его вызывает: например, `Bullet` вызывает `BossController.TakeDamage`, а `Exit` — `GameManager.WinLevel`.
5. Ищи `[SerializeField]`, `GetComponent`, `FindFirstObjectByType` и `Resources.Load`: они показывают, откуда компонент получает данные и зависимости.

Руководство объясняет назначение и поток работы. Чтобы уверенно объяснить буквально каждую строку преподавателю, полезно разбирать по одному файлу в Unity/IDE: сначала `PlayerMovement.cs`, затем `GameManager.cs`, `RuntimeLevelBootstrap.cs`, бой с боссом и UI.
